# Experiment design

## Core question

Which optoelectronic and protocol parameters control the transition from
point-to-point QKD performance to connectivity and usable capacity in realistic
geographical networks?

## Inputs

- fibre attenuation alpha;
- detector efficiency eta_det;
- dark-count probability p_dc;
- misalignment error e_d;
- signal-state intensity mu;
- error-correction inefficiency f_EC.

Do not finalise the ranges until they have been checked against the existing
simulator, the thesis assumptions, and representative device literature.

## Scenarios

- Castilla y León: 267 municipalities.
- Mainland Spain: 3102 municipalities.

Record the exact candidate-edge rule and whether link lengths are geodesic,
inflated geodesic, road-based, or derived from fibre routes.

## Outputs

Link level:

- median SKR;
- operational reach;
- usable-edge fraction.

Network level:

- largest connected component fraction;
- reachable-pair fraction;
- isolated-node fraction;
- global efficiency;
- median maximum-bottleneck capacity.

## Sampling

- Sobol base sample N = 4096.
- Six inputs.
- First- and total-order indices; explicit second-order indices disabled.
- 32768 evaluations per configuration.
- Fixed random seed recorded in the analysis code.
- 1000 bootstrap resamples for confidence intervals.
- Convergence at N = 256, 512, 1024, 2048, and 4096.

## Operational thresholds

Primary threshold: 1000 bit/s.

Robustness thresholds:

- 100 bit/s;
- 1000 bit/s;
- 10000 bit/s.

## Required robustness checks

1. Narrower ranges representing one technology generation.
2. Representative correlated detector profiles.
3. Alternative distance model.
4. Sobol-index convergence.
5. Parameter-ranking stability across thresholds.

## Integrity rule

Do not replace any RESULT marker until the corresponding output has been
generated by the analysis and recorded in a machine-readable results table.

## Deviations from this design (recorded 2026-11-17, round-3 revision)

Everything above this line is the design as written on 2026-09-17, before the
analysis pipeline existed, and is left unedited as the record of what was
pre-specified. The study that was run differs from it as follows. The
deviations were first made in commit `3dc42c7` (2026-09-18) and were not
recorded here at the time.

| Item | Pre-specified above | As run |
|---|---|---|
| Inputs | six | seven: fixed insertion loss `L0` (1-4 dB) added |
| Evaluations per configuration | 32768 = 4096 x 8 | 36864 = 4096 x 9 |
| Primary threshold | 1000 bit/s | 5e6 bit/s |
| Robustness thresholds | 100, 1000, 10000 bit/s | 1e6, 5e6, 2e7 bit/s |

Why. Under the 45 km candidate-edge rule the lowest key rate anywhere in the
parameter box is about 2.1e4 bit/s (`results/claim_support.json`), so every
link clears all three pre-specified thresholds in every sample and every
network output is constant. The threshold was therefore moved, by a scan of the
spread of the largest-component fraction (`analysis/threshold_scan.py`,
`results/threshold_scan.csv`), to the region where the outputs vary most. That
is a choice made after seeing model output, and every network-level result is
conditional on it.

Not changed: base sample size, bootstrap size, convergence sizes, the list of
robustness checks, and the four hypotheses of the manuscript. The stability
criterion of 0.02 does not appear in this document; it appears as a `\todo{0.02}`
placeholder in the manuscript of the same date.

Controls added after this document: interaction-free surrogate link model and
estimator source-set size (round 1); intermediate detector generation,
generation statistics at all three thresholds, route-factor and
decoupled-misalignment variants of the generation analysis (round 3).
